# Everest Leaderboard

لوحة صدارة مبيعات Everest Real Estate — Vue 3 + Tailwind v4 + Supabase.
إعادة بناء للإصدار الأول الذي كان يقرأ Google Sheets مباشرة من المتصفح.

## ما تغيّر عن الإصدار الأول

| | الإصدار الأول | هذا الإصدار |
|---|---|---|
| مصدر البيانات | Google Sheets API من المتصفح | Supabase (Postgres) |
| مفتاح Google | مكتوب داخل ملف الـ JS العام | داخل Edge Function فقط |
| التحديث | polling كل 30 ثانية | Realtime + احتياطي كل دقيقتين |
| أسهم الترتيب | في الذاكرة، تضيع مع كل refresh | من لقطات يومية في القاعدة |
| اللغة | إنجليزية فقط | عربية (افتراضي) + إنجليزية مع RTL كامل |
| المظهر الليلي | عبر `?theme=` فقط | زر في قائمة الإعدادات + محفوظ |
| شاشات العرض | تدوير ثابت 15ث | مدة قابلة للضبط، Wake Lock، وضع كشك |

## التشغيل محلياً

```bash
npm install
cp .env.example .env.local   # ثم املأ القيم
npm run dev
```

`.env.local` يحتاج مفتاح **publishable/anon** فقط — وهو مصمَّم للانكشاف، والحماية من RLS.

## الشاشات

| الشاشة | المحتوى |
|---|---|
| الفروع | منصة التتويج + جدول بقية الفروع |
| المستشارون | جدول كامل مع بحث بالاسم أو الفرع |
| التحليلات | اتجاه المبيعات خلال الربع + مقارنة الأرباع |

**الرسوم البيانية** تُبنى من جدول `snapshots` (لقطة يومية)، لذا تظهر رسالة
"لا يوجد تاريخ كافٍ بعد" حتى تتراكم لقطتان على الأقل. لكل رسم **توأم جدولي**
يُفتح بزر "جدول" — كل قيمة في الرسم مقروءة نصياً أيضاً.

ألوان الأرباع تدرّج أحادي اللون (ordinal) لأن الأرباع متسلسلة لا هويات مستقلة،
ومُتحقَّق منه آلياً على السطحين الفاتح والداكن. رسم الاتجاه يستخدم **الإبراز**:
المتصدّر بلون العلامة وبقية الفروع رمادية سياقية.

## التصدير

| الصيغة | ما يحدث |
|---|---|
| PNG | يلتقط اللوحة بدقة ×2. يفكّ قيود ارتفاع الشاشة أثناء الالتقاط فيخرج المحتوى كاملاً لا ما يظهر على الشاشة فقط. |
| PDF | نافذة الطباعة مع ورقة أنماط مخصّصة — ملف نصّي قابل للبحث لا صورة. |

عناصر التحكم (مبدّل العرض، الإعدادات، التصدير، البحث) تُستبعد من الناتج؛
الشعار والفترة والربع تبقى لأن التقرير يجب أن يقول أي فترة يغطّي.

صور الوكلاء من نطاق خارجي، فإن رفض CORS تلويث الـ canvas يُعاد الالتقاط مرة
واحدة بعد كتم الصور، وتظهر الأحرف الأولى بدلاً منها بدل أن يفشل التصدير كلياً.

## صفحة الإدارة

على `/?admin=1` (أو من قائمة الإعدادات ← الإدارة). محمية بـ Supabase Auth،
ولا تفتح إلا لحساب مسجَّل في `leaderboard.admins`، أو حساب عرض في
`leaderboard.demo_accounts` (يرى كل شيء، والخادم يرفض أي كتابة منه).

| التبويب | ما يفعله |
|---|---|
| الأهداف والمبيعات | جدول لكل مستشار نشط في سنة وربع محدَّدين. الأرقام مسودّات محلية ولا شيء يُكتب حتى تضغط حفظ. |
| المستشارون | إضافة وتعديل: الاسم بالإنجليزية والعربية، الفرع، الصورة، النشاط. |
| الفروع | نفس الشيء للفروع. |

### ملف Excel (تبويب «استيراد وتصدير»)

الملف المصدَّر فيه 4 أوراق: **Instructions** (إرشادات الإدخال بالعربي، وتتجاهل عند
الرفع)، و **Teams**، و **Agents**، و **Deals** (صفقات السنة: agent, date,
amount_egp, developer, project، و team للعرض فقط).

- `q*_deals` في ورقة Agents = مبيعات الربع **غير المسجّلة كصفقات**. إجمالي الربع
  = `q*_deals` + كل صفقات الربع. التصدير يكتبها بنفس المعنى، فرفع الملف تاني —
  حتى بعد المسح — يرجّع نفس الأرقام بالظبط.
- صفقة موجودة (نفس المستشار والتاريخ والمبلغ والمطوّر والمشروع) لا تتكرر.
- أي خطأ في ورقة Deals يوقف الرفع كله برقم الصف؛ لا شيء يُكتب نصّاً.
- الرفع والمسح صامتان: لا احتفالات على الشاشات (`leaderboard.silent`).

**مسح البيانات** (للمسؤول الكامل): «المبيعات فقط» (أهداف، مبيعات، صفقات،
إشعارات، سجل الترتيب) أو «كل البيانات» (ومعها الفرق والمستشارون). نسخة احتياطية
HTML تنزل تلقائياً قبله، وكلمة التأكيد تُتحقَّق على الخادم (`lb_admin_wipe`). لا
يلمس المستخدمين والأجهزة والصوتيات والرسائل والإعدادات والأخبار.

**التنشيط بدل الحذف:** إلغاء تنشيط سجل يُخفيه من اللوحة ويُبقي بياناته. الحذف
نهائي — حذف مستشار يمحو كل أهدافه ومبيعاته معه، لذا يسأل تأكيداً أولاً.

**رفع الصور** مباشرة إلى مخزن Supabase (bucket `avatars`): قراءة عامة، وكتابة
للمسؤولين فقط، بحد 2 ميجابايت وصيغ JPG/PNG/WebP. اسم الملف يحمل طابعاً زمنياً
حتى لا يعرض المتصفح نسخة قديمة مخبأة بعد الاستبدال. هذا يغني عن روابط Drive
ومشاكل إعدادات مشاركتها.

### حدود الصلاحية

schema `leaderboard` يبقى غير مكشوف عبر الـ API. كل كتابة تمر عبر دوال
`public.lb_admin_*` وأول سطر في كل واحدة `perform public.lb_require('<القسم>')`
(منذ 0022، بدل `lb_admin_guard()`). صلاحية التنفيذ ممنوحة لـ `authenticated`،
والحارس داخل الدالة هو ما يفصل صاحب الصلاحية عن أي مستخدم مسجَّل آخر.

### المستخدمون والصلاحيات (تبويب «المستخدمون»)

للمسؤول الكامل فقط. يضيف حسابات، ويحدّد لكل حساب دوراً:

| الدور | ماذا يرى ويفعل |
|---|---|
| مسؤول كامل | كل الأقسام + إدارة المستخدمين (`leaderboard.admins`) |
| محرّر | يرى ويعدّل الأقسام المختارة فقط (`leaderboard.user_access.permissions`) |
| اطلاع فقط | يرى صفحة الإدارة كاملة بلا أي كتابة |
| اللوحة فقط | يرى شاشة اللوحة، بدون صفحة الإدارة |

- الإنشاء، والحذف، وكلمة المرور الجديدة، والإيقاف تمر عبر Edge Function
  `admin-users` (تحتاج service_role، والمفتاح لا يغادرها). تتحقق أولاً من أن
  المستدعي مسؤول كامل بتوكنه هو.
- لا أحد يغيّر صلاحياته أو يحذف/يوقف حسابه بنفسه، فلا يمكن قفل آخر مسؤول بالخطأ.
- إدارة المستخدمين لا تُمنح لمحرّر، فلا يستطيع ترقية نفسه.
- كل تغيير صلاحية يُسجَّل في `leaderboard.maintenance_log` (kind = `access`).

**الدخول باسم مستخدم أو بالبريد:** خانة الدخول تقبل الاثنين، ووجود `@` هو الفاصل.
الاسم (`leaderboard.usernames`) يُترجَم إلى بريد داخل Edge Function
`username-sign-in` بمفتاح الخدمة، فالبريد لا يصل للمتصفح، والرد واحد سواء الاسم
غير موجود أو كلمة المرور خطأ. 5 محاولات خاطئة تقفل الاسم 15 دقيقة. الحساب ممكن
يكون بلا بريد: يُعطى بريداً داخلياً `<الاسم>@noemail.everest-leaderboard.app`
لا يستقبل رسائل، ولا يُعرض في الواجهة.

views الإدارة (`lb_teams`, `lb_agents`, `lb_periods`) مقصورة على
`authenticated`؛ الدور `anon` لا يقرؤها أصلاً لأنها تكشف السجلات غير النشطة.

### ترقية حساب إلى مسؤول

الأسهل من تبويب «المستخدمون». يدوياً: الحساب يُنشأ أولاً من لوحة Supabase
(Authentication ← Users)، ثم:

```sql
-- مسؤول
insert into leaderboard.admins (user_id)
select id from auth.users where lower(email) = lower('<البريد>');

-- حساب عرض للاطلاع فقط
insert into leaderboard.demo_accounts (email) values (lower('<البريد>'));
```

## معاملات الرابط

| المعامل | القيم | الأثر |
|---|---|---|
| `view` | `teams` \| `agents` \| `insights` | الشاشة المعروضة عند الفتح |
| `quarter` | `1..4` أو `q1..q4` | تثبيت ربع معيّن |
| `theme` | `daylight` \| `midnight` | المظهر |
| `lang` | `ar` \| `en` | اللغة |
| `rotate` | `on` \| `1` | تشغيل التبديل التلقائي |
| `interval` | ثوانٍ | مدة التبديل |
| `kiosk` | `1` | إخفاء كل عناصر التحكم |

مثال لشاشة المكتب: `?kiosk=1&rotate=on&interval=20&theme=midnight`

### بدون شريط العنوان

- **شاشة المكتب:** `docs/office-screen.bat` يفتح Chrome في وضع kiosk — لا شريط
  عنوان ولا تبويبات. الخروج بـ Alt+F4.
- **أي جهاز آخر:** اللوحة قابلة للتثبيت كتطبيق (`public/manifest.webmanifest`).
  في Chrome أو Edge: أيقونة التثبيت في آخر شريط العنوان، أو القائمة ⋮ ←
  «Cast, save, and share» ← «Install page as app». بعدها تفتح من أيقونتها في نافذة
  بلا شريط عنوان. على الموبايل: «Add to Home screen».

## اختصارات لوحة المفاتيح

`T` تبديل الشاشة · `R` التدوير · `F` ملء الشاشة · `S` الإعدادات · `L` اللغة · `D` المظهر

التدوير التلقائي يمرّ على لوحتَي الصدارة فقط؛ شاشة التحليلات تُفتح يدوياً.

## قاعدة البيانات

الجداول في schema `leaderboard` **غير المكشوف** عبر الـ API. الفرونت يقرأ من views في `public`:

- `lb_team_standings` · `lb_agent_standings` — الترتيب المحسوب لكل (سنة، ربع)
- `lb_rank_history` — من اللقطات، للرسوم البيانية
- `lb_previous_ranks` — آخر لقطة سابقة، أساس أسهم الصعود/الهبوط

الكتابة تمر حصراً عبر `public.lb_sync` / `lb_take_snapshot` / `lb_log_sync`
(`SECURITY DEFINER`، صلاحية التنفيذ لـ `service_role` فقط).

```bash
supabase link --project-ref mbvscayjwnuvkvolbpoz
supabase db push
```

اللوحة على مشروع Supabase مستقل («Everest Leader») منفصل عن تطبيق الموارد
البشرية. كل الملفات مطبَّقة عليه عدا `0003` و `0005` (مزامنة جوجل شيت

`0000` يُطبَّق أولاً: يعرّف `is_admin()` الذي تحتاجه سياسات التخزين في `0004`.

## Edge Function

```bash
supabase secrets set GOOGLE_API_KEY=<المفتاح الجديد> SHEET_ID=<معرّف الشيت> SYNC_SECRET=<سر عشوائي>
supabase functions deploy sheets-sync
supabase functions invoke sheets-sync --no-verify-jwt
```

> **مهم:** المفتاح الذي كان في الإصدار الأول مكشوف علناً — أبطله من Google Cloud Console
> وأصدر مفتاحاً جديداً مقيَّداً بـ Sheets API فقط قبل ضبط `GOOGLE_API_KEY`.

الدالة تقرأ نطاقَي `Agents` و `Teams` بنفس أسماء الأعمدة القديمة:
`name`, `team`, `photo`, `q1_target`..`q4_target`, `q1_deals`..`q4_deals`
(بالإضافة إلى `name_ar` الاختياري للأسماء العربية).

قالبا CSV بسيطان في `docs/sheet-template-Agents.csv` و `docs/sheet-template-Teams.csv`
لمن يريد تعبئة يدوية سريعة بلا نموذج.

**للاستخدام اليومي عبر نموذج جوجل** (بدل التعديل اليدوي في الشيت): شيت جاهز
كامل بالمعادلات والتحقق من صحة البيانات في `docs/Everest-Sales-Workbook.xlsx`،
مع `docs/setup_form.gs` الذي يُنشئ نموذج Google Form ويربطه تلقائياً بسجل
المبيعات — الخطوات كاملة في `docs/دليل_الاستخدام.md`. أعمدة Teams/Agents
النهائية فيه مطابقة تماماً لما تتوقعه هذه الدالة، فلا حاجة لأي تعديل هنا.

**قواعد القراءة:** `name` هو المفتاح الفريد — تعديله يُنشئ سجلاً جديداً لا يحدّث القديم.
الأرقام تُنظَّف من الفواصل ورموز العملة. الربع الذي هدفه ومبيعاته صفر يُتخطى تماماً
فلا يُكتب له صف. الصفوف الفارغة تُتخطى.

**الصور:** ارفعها على Google Drive، اضبط المشاركة على "أي شخص لديه الرابط"، ثم الصق
الرابط في عمود `photo` — تستخرج الدالة المعرّف وتحوّله إلى رابط عرض مباشر. إن غابت
الصورة أو تعذّر تحميلها تظهر الأحرف الأولى من الاسم بدلاً منها.

## حالة البيانات

القاعدة **فارغة** — مُسحت بيانات التحقق. اللوحة تعرض حالياً رسائل "لا توجد نتائج
بعد"، وهذا هو السلوك الصحيح: لا رجوع إلى بيانات تجريبية ما دام الاتصال ناجحاً.

املأها بإحدى طريقتين:

- **صفحة الإدارة** — أضف الفروع ثم المستشارين ثم الأرقام.
- **المزامنة من الشيت** — اضبط الأسرار وشغّل `sheets-sync` (انظر أدناه).

لإفراغها مجدداً:

```sql
truncate leaderboard.snapshots, leaderboard.sales, leaderboard.targets,
         leaderboard.agents, leaderboard.teams, leaderboard.sync_log cascade;
```
